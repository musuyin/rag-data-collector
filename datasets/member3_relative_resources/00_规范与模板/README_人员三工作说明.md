# 人员三：关联资料与数据治理 — 工作说明

## 职责边界

| 角色 | 你做什么 | 你不做什么 |
|------|----------|------------|
| 人员一 | 型号/规格结构化字段 | 不替代其字段表，只做跨实体关联 |
| 人员二 | 多模态数据集收集 | 不替代其数据卡，只登记来源与许可状态 |
| **人员三（你）** | **实体关联、来源治理、归档哈希、缺口/许可/进度、图谱关系** | 不定向写爬虫（属人员四） |
| 人员四 | 脚本、流水线、看板工程化 | 你提供可校验的人工表与关系导出 |

## 本目录结构

```
人员三_关联资料与数据治理/
├── 00_规范与模板/          # 字段定义、命名规范、工作流
├── 01_来源总表/            # 所有资料统一登记
├── 02_关联关系表/          # 厂商-型号-部件-软件-协议-漏洞
├── 03_论文与开源/          # 论文、GitHub、Zenodo 等
├── 04_安全公告与供应链/    # CVE、厂商公告、供应链
├── 05_归档与哈希/          # 归档路径、SHA-256 清单
├── 06_去重与冲突/          # 重复文件、字段冲突
├── 07_缺口许可进度/        # 缺口、许可风险、收集进度
├── 08_图谱关系导出/        # 供 Graph/知识库 的节点边表
├── 09_阶段报告/            # 阶段总报告 + 对接/ + 历史/（见该目录 README）
└── raw_archive/            # 原始文件落盘（按规范命名）
```

## 日常工作流（建议每周循环）

1. **收**：从人员一/二交接新来源；自查论文、开源、安全公告。
2. **登**：写入 `01_来源总表/来源总表.csv`，分配 `source_id`。
3. **关**：抽取实体与边，更新 `02_关联关系表/`。
4. **归**：文件放入 `raw_archive/`，算 SHA-256，记入哈希清单。
5. **检**：查重、查冲突，记入 `06_去重与冲突/`。
6. **缺**：更新缺口/许可/进度看板。
7. **出**：导出图谱节点边；写阶段报告。

## 与后续系统对接

- `08_图谱关系导出/nodes.csv` + `edges.csv` → Graph 智能查询 / 知识库
- `01_来源总表` + `07_缺口许可进度` → 人员四数据看板
- `05_归档与哈希` → 人员四复现性验证输入
